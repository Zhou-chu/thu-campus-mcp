# 身份与会话生命周期契约

本文件定义 thu-campus-mcp 在“谁是谁、会话什么时候失效”上的规则。实现分散在
`lib/app/account.mjs`、`lib/app/session-reset.mjs`、`lib/app/devices.mjs`、
`lib/app/unified-login.mjs`、`lib/app/routes/account.mjs`，这里是唯一的产品口径。

## 1. 身份边界

- **一个运行实例只持有一个校园身份**（一组清华账号凭据），不支持多用户共用同一个实例。
- 设备令牌（`tc1_…`）代表**应用会话**，不是校园身份；同一个实例可以被多台设备登录。
- GitLab 使用自管访问令牌，独立于清华统一认证，不参与“身份变更回收”。
- 网络学堂、云盘、雨课堂、座位、体育的站点会话都由校园身份派生，身份变化时必须回收。

## 2. 身份代际（generation）

- 保存在状态目录的 `account-generation.json`，只含 `{generation, updatedAt}`，**不含凭据**。
- 首次保存账号：`0 → 1`。
- 只有学号或密码**实际变化**才递增；同一组凭据重复保存保持原代际，不打断正在使用的会话。
- 清除账号一定递增。
- 代际用于判断“这组站点会话还属于当前身份吗”，不用于给设备令牌设有效期。

## 3. 变更与清除时发生什么

账号保存且代际变化时：

1. 回收校园站点会话：删除 seat / sports / learnx / id / 雨课堂 / 云盘 域的 Cookie 与 localStorage 来源，并清网络学堂授权文件；
2. 其它来源（例如 `git.tsinghua.edu.cn`）保持不变；
3. 向服务状态写入“会话已过期”信号，界面立即显示过期，而不是继续显示旧身份的“已登录”；
4. 已配对设备令牌**不受影响**——它们代表应用会话，不是校园身份。

`DELETE /api/account` 一定执行上述回收并返回新代际。

## 4. 登录提交顺序

统一账号登录（`POST /api/auth/unified`）是三阶段提交：

1. **验证**：走学校统一认证，成功只返回 `{username, commit}`，不写盘；
2. **签发**：生成设备令牌；
3. **提交**：`commit()` 写入 DPAPI 账号；失败则 `devices.revoke` 回收刚签发的令牌，接口返回失败。

不允许出现“令牌能用但账号没保存”的半完成状态。

## 5. 设备身份

- 客户端生成稳定 `deviceKey`（localStorage，UUID），登录与配对时提交；
- 有 `deviceKey` 时按 key 去重/轮换：同名的两台机器不会互相顶掉；
- 没有 `deviceKey` 的旧客户端退回“名称+平台”去重；
- 显式退出/撤销/轮换只影响目标设备：`DELETE /api/devices/<id>`、`POST /api/session/rotate`。

## 6. 失败与并发

- 并发点击「保存并登录」在事件处理器内**同步占位**，第二次点击直接被忽略（只发一次编排）。
- 登录编排逐服务独立成败，结果按 `ready / needs-manual / busy / unavailable / not-configured / queued / failed` 归因；一个服务失败不阻断其它服务。
- 需要人工验证（验证码/二次验证）时停止后续自动登录并明确提示，不在后台静默重试。
- 账号保存/清除必须走 HTTPS 或本机回环；远程明文 HTTP 直接拒绝。

## 7. 明确不承诺

- 不提供多用户共用实例；
- 设备令牌不随身份代际失效（清除账号后设备仍是已登录的应用会话，只提示校园服务需重新登录）；
- 邮箱登录用户的库内账号（`account-sync`）变更暂不触发站点会话回收；
- 真实校园的冷/暖/过期行为需本人用真实账号验收，见 #166。
