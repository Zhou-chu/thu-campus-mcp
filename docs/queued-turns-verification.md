# 工作中排队与下一轮模型修复验收

## 行为契约

- 当前轮工作时，消息输入与发送可用；发送进入当前页面的FIFO待发队列，不并发调用同一会话。
- 模型可在当前轮工作中选择，保存后只影响后续轮次。每条待发消息在真正启动时读取最新已保存模型，不在入队时绑定旧模型。
- 当前轮模型保持独立快照，覆盖模型的工具调用及工具结果续轮；没有移除服务端同会话并发保护。
- 模型保存或目录刷新未结束时等待；保存失败、停止、断流或失败时暂停待发队列，保留剩余项。已消费但失败/断流的当前轮不自动重试，避免重复请求或重复工具操作。
- 已暂停的队列需明确“继续队列”；模型修复不暗中解除暂停。队列可展开查看、取回到输入框编辑、确认后清空；清空不终止活动轮。
- 有待发项时不切到另一会话；导航到服务或设置不丢失当前页面队列。队列仅在页面内存中，不冒充服务端持久化；刷新/关闭前注册原生离开提醒。不能承诺崩溃或强制关闭后恢复。
- 停止与业务风险确认仍是独立操作，排队消息不替代或绕过写入审批。中文输入法组合状态下的Enter不提交。

后台实现本来已按轮固定模型，未修改执行器，也没有重启原后台。已打开的旧页面需在当前任务结束后刷新加载新版前端，不能在活动任务中强制刷新导致中断。

## 静态可维护性

项目自定义TypeScript AST指标，范围为主界面和上述四个纯逻辑模块：204函数，200个未越软阈，4个越软阈，0个硬超限，98.04分。

公式`round2(100 × 未越软阈函数 / 函数总数)`；软阈复杂度20/嵌套5/有效行100/参数5，硬上限50/8/200/8，至少90分且无硬超限。初次检查发现流式入口复杂度51超过硬上限50，已拆出完成与失败终态判断后重新实测通过；未放宽阈值。此为自定义维护性指标，不是Sonar或视觉评分。
