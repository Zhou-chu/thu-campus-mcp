# 审批卡修复与缺失功能记录

## 本批交付

- 待审批默认展开具体风险与动作，冻结参数不再铺满正文；外层与参数都可自行收起/展开。参数保留完整原文，内部滚动、软换行并支持桌面鼠标纵向拖高。
- 仅确认接口明确返回`decided:true`后，才记录“已允许执行/已拒绝”并自动收起、隐藏动作，保留本页面可重新展开的风险和参数。不是新增服务端持久化审计日志，也不把允许执行显示为执行完成。
- 提交期间防重复、失败就地显示错误并恢复重试；HTTP成功但决定未接受不冒充批准。请求绑定原会话，视图重绘保留提交状态并更新当前卡片；在适当情况下将焦点恢复到摘要，不抢走用户已移动的焦点。
- 新增[功能点清单](app-features.md)，从README链接。模型思考强度选择、审批模式选择均明确标为**待实现**，记录真实能力声明、白名单保存回读、下一轮生效、失败回滚和服务端防绕过的验收要求；没有添加假控件，没有放宽现有审批。

V8仅统计approval/chat-width/turn-queue/chat-home/sidebar/ui-feedback，不冒称整个应用、DOM或CSS覆盖率。AST公式为round2(100×未越软阈函数/函数总数)，软阈复杂度20/嵌套5/有效行100/参数5，硬上限50/8/200/8；要求≥90且无硬超限。

专项浏览器用80行受控冻结脚本验证默认紧凑、手动/键盘折叠、真实鼠标拖高、不截断原文、390px无横向溢出、深色与浅色、503失败后重试、`decided:false`回执不假成功、等待决定时切换设置/对话、批准/拒绝后收起、重新展开不重复执行。参数拖动初次未通过，原因是测试未把底边滚入可操作区；增加真实滚动定位后通过，未降低尺寸断言。认证旧用例同步为主动展开后核对全部冻结scope，仍保留批准前零写入、批准后一次初始化及raw写API零调用断言。

本批仅本地受控模型/工具/云盘夹具，无真实计费模型、校园或云盘写入、Docker执行；截图和日志留在忽略的本地目录。窄屏为模拟视口，不是暂停中的手机实机测试。没有重启当前预览服务或强刷用户工作会话，未重打Windows包；当前任务与队列结束后刷新加载新前端。
